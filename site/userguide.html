一、这是什么

捞捞麦是一个运行在 AI 对话里的点单助手技能。它不做一个新的点餐 App，而是把你已经在用的对话窗口，变成一个会帮你做决策的点单管家。

它要解决的问题很具体：外卖 App 把菜单、价格、优惠券全都摆在你面前了，但决策全是你的。翻菜单 5 分钟、算优惠 3 分钟、纠结热量 2 分钟，最后还是随便点一个。

捞捞麦做的事：听懂一句人话 → 查真实菜单 → 过滤优惠券 → 调用官方算价 → 给出 2-4 个可解释的方案 → 你点头才下单。

它和「问大模型」的区别

对比项通用大模型捞捞麦
菜单价格靠记忆，可能过期官方接口实时查询
优惠券不知道你有什么券查你卡包 + 门店可领券
算价自己算，容易错官方算价接口验证
下单做不到确认后可创建订单
编造风险高数据缺失时如实说"不确定"

二、三种使用方式

方式一：在 WorkBuddy 对话中使用（推荐，最真实）

技能已安装，无需任何配置，直接说话即可：

帮我点麦当劳，预算25块，想吃带肉的，不要太撑，自提

触发关键词：点单、点餐、吃什么、帮我点麦当劳、帮我点瑞幸、预算点餐、优惠点餐、AI点单管家、MCP点单、菜单推荐、比价点餐。

① 你说需求 —— 「帮我点麦当劳，预算25块，想吃带肉的，别太撑」
↓
② 捞捞麦给方案 —— 2-4 个，每个含商品组合 / 原价 / 实付 / 省了多少 / 热量 / 推荐理由
↓
③ 你选一个 —— 回复「方案 1」
↓
④ 它出确认卡 —— 门店 / 取餐方式 / 商品 / 优惠券 / 实付金额，逐项核对
↓
⑤ 你确认才下单 —— 回复「确认下单」创建订单；回复其他内容一律取消
全程不会自动支付、不会在你没点头时下单。

方式二：在线体验（给评委 / 演示用）

三、你能怎么说

接受自然语言，不用记命令。以下信息随口说几个都行：

你能提供的举例不说会怎样
预算上限「25块以内」「预算30」默认按 25 元
口味偏好「带肉的」「清淡」「想吃辣」「不辣」不限制
份量/热量「不想太撑」「低热量」「少油」「小份」不限制
忌口「不要香菜」「不吃辣」不限制
取餐方式「堂食」「自提」「配送」默认到店自提
门店「华立学院店」默认用你收藏的门店

示例句子（都可以直接用）：

帮我点麦当劳，预算25块，想吃带肉的，不要太撑，自提
吃什么好？20块以内帮我点个清淡的早餐
我和同学两个人，100块，想吃点有肉的
帮我看看有什么优惠能用
我在美团看到一张19.9的单人餐券，和官方比哪个划算
用活力风帮我点

四、它会怎么答

每个方案必须包含 6 项，缺一不可：商品组合、原价、用券后价格（实付）、节省金额、热量或份量说明、推荐理由。

三条硬规矩

  • 价格或优惠无法确认时，明确提示「价格需以下单页为准」，绝不猜数字
  • 预算不够或门店无合适商品时，必须给替代建议（放宽约束 / 换门店 / 调份量），而不是说"没有"
  • 下单前必须输出确认卡，你点了确认才继续

五、七个核心能力

能力说明
自然语言理解双通道解析：大模型负责理解（可选），规则解析兜底，断网也能用
真实菜单查询调用官方 MCP 接口，返回门店实时在售商品、价格、促销标记
优惠券三重校验卡包券 + 门店可用券 + 可领未领券；按日期/星期/渠道过滤，输出 ✅可用 / 🎁可领 / ❌不可用（含原因）
官方算价验证优惠金额一律取算价接口返回值，不自算；数据缺失时拒绝编造
营养估算官方营养库匹配热量；新品无数据显示「热量数据缺失」，不用近似值
多渠道比价官方实付价 vs 你提供的美团/抖音团购券，同台对比（外部价标注"未验证"）
双主题输出默认简洁版；说「用活力风」切换红金活力主题（原创设计）

六、命令行用法（开发者）

环境：Python 3.10+，无第三方依赖。脚本在 skill/scripts/ 目录。

6.1 主流程

# mock 模式（无 MCP Server 时演示链路）
python scripts/main.py "预算25块，想吃带肉的，不要太撑" --pickup_type 自提

# 完整参数
python scripts/main.py "帮我点麦当劳" \
    --budget 25 --store_id 1400583 \
    --pickup_type 自提 --mcp_server mcd --no-llm

启用大模型意图解析（可选，不配也能用）：

export MCP_ORDER_LLM_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
export MCP_ORDER_LLM_API_KEY="你的密钥"
export MCP_ORDER_LLM_MODEL="qwen-plus"

支持任意 OpenAI 兼容接口：通义千问 / Kimi / DeepSeek / Claude 均可。

6.2 算价校验

python scripts/price_calculator.py '{"original_price":30.0,"discounted_price":25.0,"valid":true}'
# 真实麦当劳 MCP 格式（单位：分，自动转元）
python scripts/price_calculator.py '{"originalPrice":2900,"price":2090,"discount":810}'

数据不完整时退出码 2，并提示「价格需以下单页为准」。

6.3 优惠券过滤

python scripts/coupon_filter.py '[{"id":"C1","name":"11.9元麦辣鸡腿堡",
  "valid_from":"2026-10-26 10:30","valid_to":"2026-10-30 23:59",
  "weekdays":[1,2,3,4,5],"channels":["到店专用"]}]' \
  --channel 到店 --now "2026-10-24 14:00"

6.4 确认卡生成

python scripts/order_confirm.py --store "麦当劳科技园店" --pickup_type 自提 \
    --items '[{"name":"麦香鸡腿堡","qty":1,"price":18.0}]' \
    --total 18.0 --theme cute

6.5 下单链路

# 第一步：只出确认卡，绝不下单
python scripts/place_order.py --store "麦当劳科技园店" \
    --items '[{"name":"麦香鸡腿堡","qty":1,"price":18.0}]' --total 18.0

# 第二步：确认（默认仍是 dry-run）
python scripts/place_order.py ... --confirm "确认下单"

# 真实下单（口令必须严格等于「确认下单」）
python scripts/place_order.py ... --confirm "确认下单" --execute --mcp_server mcd

6.6 外部渠道比价

python scripts/deal_compare.py \
    --mcp '{"originalPrice":2900,"price":2090,"discount":810}' \
    --external '[{"platform":"美团","title":"单人餐团购券","price":19.9}]'

七、换模型 / 换餐饮品牌

这个作品是可替换架构，两层都能换：

  • 换模型：改三个环境变量即可，references/prompt_template.md 可替换系统提示词
  • 换餐饮品牌：参照 references/mcp_config_example.json 配置新的 MCP Server

接入步骤：

  1. 把配置写入 ~/.workbuddy/mcp.json，API 密钥填在 env 字段
  2. 打开 WorkBuddy 连接器管理页，对新 Server 点「信任」启用（不会自动激活）
  3. 接入前必读 references/mcd_tool_map.md——记录了实测踩过的坑
坑位提醒：算价接口返回单位是「分」不是元；beType/orderType 有组合矩阵；卡包券接口不做门店校验必须自己过滤；新品在营养库查不到要降级处理而不是猜。密钥一律走环境变量，不硬编码、不提交仓库。

八、常见问题

Q：推荐了用不了的券？
A：券会先过三重过滤（日期 / 星期 / 渠道），用不了的会明确标注原因和生效时间，比如「10/26 起可用」。

Q：为什么有的商品没有热量数据？
A：官方营养库未收录的新品，会显示「热量数据缺失」。捞捞麦不会用相近商品的热量去编一个数字。

Q：能比美团、抖音的团购价吗？
A：可以，但需要你提供券面信息（截图或文字都行）。当前没有美团/抖音官方数据接口，外部价格一律标注「未验证，以平台下单页为准」，不会假装能查到。

Q：它会偷偷帮我下单吗？
A：不会。下单需要你明确回复「确认下单」这四个字，其他任何回复都视为取消，而且它不碰支付环节。

Q：想要更有活力的风格？
A：说「用活力风」，确认卡和文案会切换成红金活力主题。该主题为原创设计，不使用任何第三方 IP 素材。

Q：营养信息能当饮食建议吗？
A：不能。营养数据仅供参考，不构成医疗建议。

九、安全红线（六条）

红线具体约束
不支付绝不替用户完成支付，支付一律在品牌官方渠道完成
不自动下单口令必须严格等于「确认下单」，否则一律取消
不编造价格算价接口没返回就如实说"以下单页为准"
不编造外部价美团/抖音等外部价格只能来自用户提供，标注未验证
不擅自领券领取优惠券会改变账户状态，必须先获得用户同意
营养仅供参考明确标注不构成医疗建议
代码层面已落实：不硬编码任何 API Key / 商户密钥 / 支付信息；算价数据缺失时抛 PriceDataError 阻止继续；确认卡缺门店、商品、金额时拒绝生成。
