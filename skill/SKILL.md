# mcp-order-agent — MCP 点单 Agent

## 目的

将用户的自然语言点单需求转化为结构化约束，通过餐饮 MCP Server 的工具链（菜单、优惠券、算价、营养信息）检索并验证，生成 2-4 个可解释的点单方案，经用户确认后再调用下单工具。本技能不直接替用户支付，不在无确认的情况下创建订单。

## 触发条件

用户消息包含以下任一情况时使用本技能：

- 关键词：点单、点餐、吃什么、帮我点麦当劳、帮我点瑞幸、预算点餐、优惠点餐、AI点单管家、MCP点单、菜单推荐、比价点餐
- 用户提出带预算/口味/热量约束的餐饮选择需求

## 适用 / 不适用

**适用：**
- 自然语言表达点单需求
- 结合优惠券、实付价格、热量或份量约束做决策
- 需要多个备选方案而非单一推荐
- 开发者接入不同大模型或不同餐饮 MCP Server

**不适用：**
- 直接替用户完成支付
- 未经用户确认创建订单
- 输出未经算价工具验证的优惠金额
- 提供医疗级饮食建议

## 输入参数

| 参数 | 说明 |
|---|---|
| user_query | 用户原始自然语言需求（必填） |
| budget | 预算上限，可为空 |
| preferences | 口味偏好（带肉、清淡、辣、不辣等），可为空 |
| constraints | 约束条件（不想太撑、低热量、少油、忌口等），可为空 |
| store_id | 门店 ID，可为空 |
| pickup_type | 取餐方式：堂食 / 自提 / 配送，可为空 |
| model_provider | 可选大模型提供方：qwen、kimi、deepseek、claude |
| mcp_server | 可选餐饮 MCP Server 标识 |

参数可从 user_query 中自动解析，未提供的保持为空并在输出中说明默认行为。

## 工作流

1. **解析意图**：从 user_query 提取预算、口味、忌口、热量/份量约束、门店和取餐方式；无法解析的项保持为空，不要猜测。
2. **检索菜单**：调用菜单 MCP 工具（如 `query-meals`）获取可售商品；若 store_id 为空先查询附近门店。
3. **获取优惠**：三路收集优惠信息——
   - `query-my-coupons`（用户卡包已有券）：必须用 `scripts/coupon_filter.py` 按日期/星期/渠道过滤；
   - `query-store-coupons`（当前门店+取餐方式下可用券）：作为门店维度的补充校验；
   - **可领未领的券**：如存在可领取的券，在推荐后提醒用户"有 N 张券可领"，经用户同意后调用 `auto-bind-coupons` 一键领取（该操作改变用户账户状态，必须先获同意）；团餐场景再查 `query-promotions`（满减/满折规则）。
4. **算价**：调用算价 MCP 工具（如 `calculate-price`）对候选组合计算实付价格。优惠金额只采用算价工具返回值。
4.5. **外部渠道比价（可选）**：用户提供美团/抖音等团购券信息（价格、内容、有效期）时，用 `scripts/deal_compare.py` 与官方实付价同台对比。外部价格一律标记"未验证，以平台下单页为准"；无官方数据连接器时**不得抓取或编造**外部平台价格。
5. **估算热量/份量**：调用营养信息 MCP 工具（如 `list-nutrition-foods`）估算组合热量或份量。
6. **生成方案**：产出 2-4 个候选方案，按性价比、优惠力度、用户偏好排序。
7. **输出推荐**：使用 `assets/order_card_template.md` 格式输出可解释推荐，等待用户确认。
8. **确认下单**：用户明确确认后，调用下单 MCP 工具；下单前输出确认卡（可使用 `scripts/order_confirm.py` 生成）。

## 脚本

- `scripts/main.py`：主执行脚本。意图解析（可选 LLM，规则兜底）→ MCP 工具调用 → 生成候选方案。LLM 经环境变量启用：`MCP_ORDER_LLM_BASE_URL` / `MCP_ORDER_LLM_API_KEY` / `MCP_ORDER_LLM_MODEL`（OpenAI 兼容接口），未配置自动回退规则解析；`--no-llm` 可强制规则。本地调试：`python scripts/main.py "预算25块，想吃带肉的，不要太撑" --budget 25 --pickup_type 自提`
- `scripts/price_calculator.py`：兼容两种算价格式（简化元单位 / 真实 mcd-mcp 分单位），自动归一化并计算节省金额，数据不完整抛错提示"价格需以下单页为准"。
- `scripts/coupon_filter.py`：按有效期/适用星期/渠道校验券当前可用性并输出原因；query-my-coupons 返回的券必须经此过滤后再用于推荐。
- `scripts/order_confirm.py`：生成下单确认卡文本，包含门店、取餐方式、商品、优惠券、实付金额。支持 `--theme default|cute` 两套主题（cute 为原创可爱风，见 `references/cute_theme.md`）。
- `scripts/place_order.py`：下单链路。无口令只出确认卡；口令严格等于「确认下单」才继续；默认 dry-run，`--execute --mcp_server <id>` 才真实调用 MCP 下单。
- `scripts/deal_compare.py`：外部团购渠道（美团/抖音等）与官方实付价同台比价；外部价格一律标"未验证，以平台下单页为准"。

## 参考资源

- `references/mcp_config_example.json`：MCP Server 配置示例（mcp.json 格式，不含真实密钥）。开发者可替换 model_provider 与餐饮 MCP Server。
- `references/prompt_template.md`：点单 Agent 系统提示词模板，方便替换为自定义提示词。
- `references/mcd_tool_map.md`：麦当劳 MCP 工具实测地图——beType/orderType 矩阵、算价单位（分）、特调 key 规则、券校验坑等。接入真实 Server 前必读。
- `references/cute_theme.md`：原创可爱风主题指南（粉白配色、蝴蝶结元素、软萌语气），**不使用任何受版权保护的 IP 素材**。用户偏好可爱风格时按此输出。

## 输出主题

默认简洁版；用户表达偏好可爱/少女心/粉色风格时，切换 cute 主题（确认卡用 `assets/order_card_template_cute.md`，文案按 cute_theme.md）。关键数字（价格/热量/有效期）和安全提示在任何主题下都必须准确清晰。

## 输出规范

每个方案必须包含：商品组合、原价、用券后价格、节省金额、热量或份量说明、推荐理由。

- 价格或优惠无法确认时，明确提示"价格需以下单页为准"。
- 有可领取但未领取的券时，在方案后追加"🎁 可领券提醒"，列出券名与领取方式，不自动领取。
- 预算不足或门店无合适商品时，给出替代建议（放宽约束、更换门店、调整份量）。
- 下单前必须输出确认卡（门店、取餐方式、商品、优惠券、实付金额），获得用户明确同意后才调用下单工具。

## 安全约束

- 禁止在任何文件中硬编码 API Key、商户密钥或用户支付信息。
- 涉及下单、支付、地址、手机号等敏感操作时必须二次确认。
- 营养信息仅作参考，不得表述为医疗建议；用户有特殊健康状况时建议咨询医生。
- MCP 工具返回数据不完整时，不得编造价格或优惠；如实说明缺失项。
- 外部平台（美团/抖音等）价格只能来自用户提供，一律标注"外部渠道，以平台下单页为准"；无官方连接器时不得抓取、推测或编造。
